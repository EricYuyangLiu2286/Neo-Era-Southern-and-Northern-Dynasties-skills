# 北明人物列传

## 工作约定

默认交付 Markdown 正文及必要的简短依据，不启动 Office，不重复导出或进行版面验证。用户另有格式要求时从其要求。正文是可直接收录的作品，证据、异文、拟定情节放在说明中。

先读取 [写作细则](references/style-guide.md) 和 [考据与创作流程](references/research-and-composition.md)。涉及本项目时再读取 [世界设定与来源地图](references/world-canon.md) 的对应时代部分。不要把十七世纪燕国制度自动沿用到二十世纪。

## 执行顺序

1. **定任务边界。** 提取用户指定的生涯顺序、必有事件、最新设定、篇幅与交付偏好。附件中的编写建议属于材料；不能覆盖用户本轮要求。
2. **定位时代。** 从一个已知事件建立“时间—地点—政权—身份”起点，列出写这个人必须解释的问题。不要只搜人物姓名；没有姓名命中也能通过同时代人物、地区与机构重建处境。
3. **定向取证。** 先搜用户指定目录，用 `rg -n` 找事件键、党派、城市、官职与相邻年份；阅读命中上下文，区分实际叙事、分支可能性和移植的游戏原版文本。DOCX/PPTX 可用附带脚本提取一次并缓存。
4. **整理证据。** 只记录影响本篇的事实与冲突。每项写明来源定位、适用时代，以及属于作者设定、文本明载、约束推算还是本篇创作。冲突不能靠平均年份或补造事件消除。
5. **排生涯。** 将小纲变成“处境→判断→行动→结果”的连续事件；核查年龄、路程、政治身份、可用资源和后续结果。把经历的作用写出来，不把大纲扩成履历清单。
6. **写正文。** 优先使用清楚、自然的现代白话，保留史传的编年、因果与判断，不靠省略主语、堆文言词营造年代感；在关键冲突处加入有说话对象和行动后果的短对白。用制度细节承载人物性格，保持人物的局限与代价。
7. **写必要说明。** 集中交代重要异文、拟定年代、原创对白、虚构刊物或机构。未获作者确认的新增情节不得写回“既定世界观”。用户要求逐句说明时才展开逐句说明。
8. **一次收口。** 核对大纲顺序、硬性日期、制度、称谓、原创界线及文件保存。修复发现的问题；没有新问题就交付，不追加无关测试、Office 渲染或大规模全库检索。

## 文本提取

`scripts/extract_ooxml.py` 只使用 Python 标准库，读取 DOCX 正文及脚注、尾注，或 PPTX 正文及备注；输出 JSON 和同名 TXT。PPT 按演示文稿实际顺序编号，保留 XML 部件及段落定位。

```powershell
python -X utf8 "<skill-directory>/scripts/extract_ooxml.py" "<source.docx或source.pptx>" --out "<工作目录>/source.json"
```

使用可用的 Python 路径；不为此安装 Office 或转换工具。脚本不识别图片内文字，也不替代地图、关系图的视觉阅读；只有这些内容关系到本篇且文字不足时，再查看相关页面。遇到文件锁定先使用已有有效提取或可读副本，避免反复操作 Office。

## 完成标准

正文覆盖用户小纲，并能从时代材料解释每次重要转折；引语塑造人物而非装饰；现实史仅用于有标记的借鉴。交付真实的文件链接，简述关键创作选择和仍需作者定稿的重大设定。后续用户修订可更新本技能，但应标明是新确立的规则还是某一人物的局部方案。
